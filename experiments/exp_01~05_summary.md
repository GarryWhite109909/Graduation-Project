# exp_01~05 零样本推理基线总结

> 本文件将 exp_01 至 exp_05 五个实验的核心结论串起来，作为论文第 4 章的速览。每个实验的详细报告见对应 `exp_0x_report.md`。

---

## 研究问题

在不进行任何训练的情况下，本地部署的开源 7B 代码大模型能否完成代码漏洞检测？RAG、Prompt 工程等无训练增强手段的能力边界在哪里？

---

## 实验一：能力摸底（exp_01）

- **样本**：14 段典型漏洞代码（SQL 注入、XSS、命令注入、路径穿越、硬编码密钥、不安全反序列化）+ 2 段安全对照。
- **模型**：`qwen2.5-coder:7b`
- **结论**：
  - 召回率 100%、误报率 0%、准确率 100%
  - 平均耗时 7.65s/样本
  - 本地 7B 开源模型已具备典型漏洞的零样本识别能力

---

## 实验二：与传统工具对比（exp_02）

- **对比对象**：Bandit、Semgrep
- **关键样本**：`path_traversal_01.py` 使用 `os.path.join(base_dir, user_input)`
- **结论**：
  - Bandit 与 Semgrep 均未报错（规则认为 `os.path.join` 是标准库推荐用法）
  - LLM 正确识别出 `os.path.join` 不做路径规范化，存在路径穿越风险
  - **核心差异**：传统工具依赖固定规则，LLM 能理解 API 语义与绕过场景

| 指标 | Bandit | Semgrep | LLM (qwen2.5-coder:7b) |
|---|---|---|---|
| 典型样本准确率 | 75.0% | 78.6% | 100% |
| 单样本耗时 | ~0.5s | ~2s | ~7.65s |
| 输出自然语言解释 | ❌ | ❌ | ✅ |
| 输出修复代码 | ❌ | ❌ | ✅ |

---

## 实验三：RAG 知识库增强（exp_03）

- **知识库**：72 条手工编写的 CWE/OWASP 知识条目
- **检索器**：ChromaDB + `bge-small-en-v1.5`
- **结论**：
  - 典型样本上 RAG+LLM 准确率保持 100%
  - 修复答案泄露后，RAG 对难样本的检测能力提升有限
  - 模型基座已掌握典型漏洞模式，RAG 的价值更多体现在可解释性与知识可扩展性

---

## 实验四：难样本压力测试与消融（exp_04）

- **样本**：87 段 v3 修复后样本（典型 36 + 安全 18 + 难 27 + 噪音 6）
- **关键结论**：
  - 纯 LLM 多数表决：recall 83.3%、FPR 33.3%、accuracy 78.2%
  - 6 模型横向对比：`gemma4:12b/26b` 最优（accuracy 94.3%），`deepseek-coder-v2:16b` FPR 最高（44.4%）
  - RAG 消融四组对照（A: 相关 CWE / B: 随机 / C: 不相关 / D: 等长）显示：修复答案泄露后，RAG 未带来统计显著的检测提升

---

## 实验五：Prompt 工程消融（exp_05）

- **策略**：零样本 / Few-shot / 思维链（CoT）/ 安全模式白名单
- **结论**：
  - CoT 召回率 95%，为最优单一策略
  - 各策略在 FPR 与稳定性上各有取舍
  - Prompt 工程能提升判定质量，但无法替代模型层面的领域知识注入

---

## 共同结论

1. **本地 7B 开源模型已具备典型漏洞识别能力**，但在难样本、绕过式过滤、CWE 精确归因上存在明显瓶颈。
2. **RAG 与 Prompt 工程很快触顶**，无法系统性提升 CWE 归因准确率与真实 CVE 泛化能力。
3. **需要训练**：零样本能力不足以支撑工程化安全审计，必须引入监督微调。
4. **训练方向**：不应追求"风格微调"或"增大 LoRA 容量"，而应通过数据工程提升训练数据的可信度与 CWE 标注一致性。
