# 第1章 绪论

## 1.1 研究背景

软件安全漏洞造成的经济损失与社会影响持续扩大。IBM《2024 年数据泄露成本报告》显示，全球单次数据泄露事件平均损失达到 488 万美元，较 2023 年增长 10%，为历年最大增幅；其中由系统漏洞利用引发的泄露事件占比持续位于前列。中国国家互联网应急中心（CNCERT）发布的《2024 年上半年我国互联网安全态势报告》指出，上半年收录的通用软硬件漏洞数量同比增长 17.9%，Web 应用层漏洞仍为攻击者主要入口。在漏洞数量持续增长的背景下，代码安全审计在软件开发生命周期中的位置前移，成为 DevSecOps 实践的关键环节。

工业界长期依赖基于规则与数据流的静态应用安全测试（SAST）工具，如 Bandit、Semgrep、CodeQL 等。这类工具的核心机制是模式匹配与污点流分析，对已知漏洞模式（CWE-89 SQL 注入、CWE-78 命令注入、CWE-22 路径穿越等）检出速度快、误报可控，在 CI/CD 流水线中表现出良好的工程稳定性。然而，规则匹配的边界在面对复杂业务逻辑、绕过式过滤、跨函数污点流以及非典型漏洞变体时迅速收紧。本研究的对比实验（详见第 4.2 节）显示，在一段使用 `os.path.join` 拼接用户输入的路径穿越样本上，Bandit 与 Semgrep 均未报错，而本地 7B 参数规模的大语言模型 Qwen2.5-Coder-7B 正确识别出 `os.path.join` 不构成安全边界、攻击者可通过 `../` 实现目录穿越的风险。规则工具对"看似标准库推荐用法实则可绕过"的场景缺乏语义层判断，这一局限难以通过扩充规则集根本性解决。

大语言模型（Large Language Model, LLM）的兴起为代码安全审计提供了新的技术路径。GPT-4、Claude 3、Gemini 1.5 等闭源模型在 SWE-bench、BigVul 等代码安全评测集上展现出接近人类安全工程师的判定能力，但其闭源、按 token 计费、数据需上传云端的使用模式，与代码作为核心资产对保密性、合规性、可审计性的要求形成冲突。开源代码大模型 Qwen2.5-Coder、DeepSeek-Coder、CodeLlama 等的发布，使得在本地 GPU 上部署具备代码理解能力的 LLM 成为可能，但通用代码模型在安全领域的零样本表现仍存在三类瓶颈：一是漏洞模式知识盲区，如将参数化查询的 `?` 占位符误判为字符串拼接；二是判定边界过度敏感，对安全对照样本产生幻觉式误报；三是 CWE 分类能力薄弱，常将路径穿越错标为命令注入、将反序列化错标为代码注入。直接将通用代码模型用于安全审计，召回率、误报率与 CWE 归因准确率均无法满足工程要求。

如何在不依赖闭源 API 的前提下，通过监督微调与数据工程将通用代码大模型转化为网络安全专用模型，并在消费级 GPU（16 GB 显存）上完成训练与推理，是本研究要回答的核心问题。2026-07-22 本研究将训练基座从 Qwen2.5-Coder-7B 切换为 Qwen3-8B，在修复评估基础设施后建立了新的可信基线，并围绕监督微调（SFT）迭代优化 CWE 归因能力。

## 1.2 研究意义

### 1.2.1 学术意义

本研究在参数高效微调（PEFT）方法体系内探索"风格微调"与"数据可信度"的边界。当前主流的 LoRA、QLoRA、rsLoRA 等方法主要面向指令跟随与下游任务适配，默认假设是增大适配器容量即可承载更多任务知识。本研究在 Qwen3-8B 强基座上迭代 SFT 数据版本时发现：单纯增大 LoRA rank（Qwen2.5 时代 Phase 2 的 r=32）并未带来知识注入，反而使误报率暴涨 19.2 个百分点；真正带来提升的是数据质量——包括 CWE 标注统一、CoT 重写、训练-测试泄漏清洗。这一结果表明，在已经具备较强代码理解能力的高基座模型上，**数据可信度比模型容量更关键**，为后续 PEFT 研究中"何时需要更大数据、何时需要更大模型"的方法选择提供了实证依据。

本研究还揭示了消费级 GPU 上偏好优化的硬件边界。直接偏好优化（DPO）理论上可通过偏好对降低误报率，但本地 16 GB AMD RDNA4 GPU 无法承载 8B 模型的 policy + reference 双前向：8bit 量化触发 OOM，4bit NF4 量化虽能装下两个模型但梯度无法正确回传到 LoRA 层，导致训练无效。该发现为算力受限场景下的训练方法选择提供了边界条件。

### 1.2.2 工程意义

本研究的工程价值体现在三个方面。第一，系统在 AMD Radeon RX 9060 XT 16 GB 消费级显卡上完成全部训练与推理，通过 QLoRA 4-bit 量化、rsLoRA、AOTRITON attention、TunableOp 离线调优等技术组合，将 8B 模型的 SFT 训练显存占用压缩到 16 GB 以内。这一结果表明，本地化部署的网络安全专用模型不必依赖数据中心级算力，中小型安全团队具备自建能力。

第二，系统输出的判定结果包含自然语言解释、漏洞类型（CWE 编号）、source-sink 污点路径与可执行修复代码，而非传统工具的"漏洞类型 + 规则编号 + 行号"三元组。在人工审计环节，审计员对单条告警的理解时间从逐条核对规则文档的 30 分钟级降低到阅读一段自然语言解释的 5 分钟级，这一差异在漏洞数量大、修复时间紧的场景下具有实质性意义。

第三，系统的训练数据、训练脚本、评估脚本、实验报告、模型 adapter 均以可复现的方式组织。实验结果文件按时间戳命名并集中登记在 `EXPERIMENT_LEDGER.md`，评估口径同时给出宽松/严格召回率，并采用真实 CVE-fix 数据集验证合成集指标的可信度。这一工程规范为后续研究提供了可比对的基线。

## 1.3 研究问题与目标

### 1.3.1 研究问题

本研究围绕以下四个递进问题展开：

**问题 1**：在不做任何训练的前提下，本地部署的开源 7B/8B 代码大模型能否完成代码漏洞检测任务？其能力边界在哪里？

**问题 2**：RAG 知识库增强、AST 代码切片、Prompt 工程等无训练手段能在多大程度上提升零样本推理的判定质量？这些手段的能力天花板在哪里？

**问题 3**：在已经具备较强代码理解能力的 8B 强基座上，通过 QLoRA 监督微调能否提升 CWE 精确归因能力？数据质量（标注一致性、CoT 质量、泄漏控制）对最终指标的影响有多大？

**问题 4**：直接偏好优化（DPO）能否进一步降低误报率？在 16 GB 消费级 GPU 上训练 8B DPO 的硬件边界在哪里？

### 1.3.2 研究目标

本研究旨在构建一个本地部署、可持续改进的代码安全审计系统，具体目标如下：

1. 在 87 段覆盖 34 类 CWE 的多语言代码样本上，建立零样本推理基线，量化 LLM 与传统 SAST 工具的能力差异；
2. 通过 RAG 消融对照、Top-K 对比、Prompt 工程消融系统评估无训练手段的能力边界；
3. 在 Qwen3-8B 上通过多版本 SFT 数据迭代，提升 CWE 归因准确率（strict_recall）与真实 CVE 泛化能力；
4. 尝试用 DPO 降低误报率，并分析本地 16 GB GPU 上的不可行性；
5. 全流程在 16 GB 显存的消费级 GPU 上完成，训练与推理代码、数据、adapter、评估结果均以可复现方式提供。

## 1.4 主要贡献

本研究的主要贡献概括为以下五点。

**贡献 1：完整的零样本推理基线与能力边界量化。** 在 87 段 v3 修复后样本（覆盖 34 类 CWE、4 种编程语言）上完成 5 个实验（exp_01~exp_05），系统量化了 Qwen2.5-Coder-7B 的零样本能力：典型样本准确率 100%，难样本多数表决准确率 78.2%，CoT Prompt 策略召回率 95% 为最优单一策略。通过 RAG 四组消融对照实验证明，在修复答案泄露后，RAG 未带来检测能力提升，模型基座已掌握典型漏洞模式，RAG 的价值更多体现在可解释性与知识可扩展性。

**贡献 2：评估基础设施可信化。** 2026-07-22 切换至 Qwen3-8B 后，将 `max_tokens` 从 1024 提升到 2048，使 parse_fail 从 18/87 降至 0/87，暴露真实 FPR 27% 与 strict_recall 46%。同时构建 8 样本真实 CVE-fix 测试集，发现合成集 recall 比 CVE-fix 高出 59.2 个百分点，证明合成集不能替代真实漏洞泛化评估。

**贡献 3：QLoRA SFT 数据迭代提升 CWE 归因能力。** 历经 v2/v3/v4/v5/v6 五个数据版本迭代，最终 `train_chatml_v5_clean.jsonl` 在清洗 100 条训练-测试泄漏样本、新增 10 条弱密码学样本后，使合成集 strict_recall 从 0.459 提升至 0.590（+13.1pp），CVE-fix recall 从 0.375 提升至 0.571（+19.6pp），同时保持合成集 recall 1.000。v4 因训练-测试泄漏被废弃、v6 hard-negative 因负迁移被归档，证明**数据可信度比指标绝对值更重要**。

**贡献 4：消费级 GPU 上 DPO 的不可行性分析。** 在本地 16 GB AMD RDNA4 GPU 上尝试 8bit、fp16、4bit 三种 DPO 配置：8bit 量化 OOM 黑屏，4bit NF4 量化虽能运行但 grad_norm=0、loss=ln(2) 不下降，所有 DPO 指标归零。根因为 DPO 的 policy + reference 双前向超出 16 GB 显存承载能力，且 4bit 量化下梯度无法正确回传到 LoRA 层。该结论为算力受限场景下的偏好优化方法选择提供了边界条件。

**贡献 5：消费级 GPU 上的完整训练流水线工程实践。** 在 AMD Radeon RX 9060 XT 16 GB 显卡上，通过 QLoRA 4-bit NF4 量化、rsLoRA（缩放因子 1/√r）、AOTRITON Triton Flash Attention、TunableOp 离线 GEMM 调优等技术组合，将 8B 模型的 SFT 训练显存压缩到 16 GB 以内。整套训练-评估-对比流水线以 Shell + Python 脚本形式提供，实验结果按时间戳命名保留历史版本，关键运行登记在 `EXPERIMENT_LEDGER.md`。

## 1.5 论文组织结构

本论文共分六章，组织结构如下。

**第 1 章 绪论。** 阐述研究背景、研究意义、研究问题与目标、主要贡献与论文组织结构。

**第 2 章 相关工作。** 从三个角度梳理文献：传统静态应用安全测试工具（Bandit、Semgrep、CodeQL）的能力与局限；大语言模型在代码安全审计中的应用现状（零样本推理、RAG 增强、微调路径）；参数高效微调方法（LoRA、QLoRA、rsLoRA、DPO）。

**第 3 章 研究方法与系统设计。** 介绍系统的四层架构：数据层（CVE/CWE/OWASP 知识、CoT 样本、87 段合成测试集、CVE-fix 真实测试集）、训练层（QLoRA SFT、DPO 尝试）、推理层（AST 代码切片、RAG 检索、LLM 推理）、评估层（宽松/严格召回率、FPR、CVE-fix 真实集验证）。

**第 4 章 零样本推理基线实验。** 报告 exp_01~exp_05 五个实验：能力摸底、传统工具对比、RAG 知识库增强、难样本压力测试与消融、Prompt 工程消融。本章回答问题 1 与问题 2。

**第 5 章 网络安全专用模型训练。** 报告 exp_06 的 P0~P3 训练实验：P0 parse_fail 修复、P1 CVE-fix 真实集校准、P2 SFT 数据迭代（v2→v6）、P3 DPO 本地不可行性分析。本章回答问题 3 与问题 4。

**第 6 章 总结与展望。** 总结本研究的主要工作与结论，讨论局限性（CVE-fix 样本量小、strict_recall 未达 70% 目标、DPO 受硬件约束），展望未来研究方向（云 GPU 跑 DPO、扩充真实 CVE-fix 数据、针对性补充缺失漏洞模式、错题增强闭环、前后端工程化）。

**附录** 给出环境搭建、数据构建、训练命令、评估命令的完整复现指南，以及 87 段测试样本的清单与 ground truth 标注。
