# 毕业论文写作大纲

## 论文题目(暂定)

基于大语言模型的代码安全审计系统设计与实现

## 答辩核心故事线

传统静态分析工具(Bandit/Semgrep/CodeQL)在 CI/CD 流水线中对已知漏洞模式高效,但面对绕过式过滤、跨文件污点流、复杂业务逻辑时力不从心。本系统以本地部署的开源大语言模型为基座,先通过 RAG 知识库与 AST 代码切片建立零样本推理基线(exp_01~05),验证 LLM 在语义理解层面对传统工具的差异化价值;再于 2026-07-22 将微调基座切换为 Qwen3-8B,通过监督微调(SFT)迭代优化 CWE 归因与真实 CVE 泛化能力。

整个训练走"**本地探索 → 云端放大**"双轨路线:先在本地消费级 16 GB AMD RDNA4 显卡上,以 4bit QLoRA 完成 v2~v9 共 9 版 SFT 迭代,揭示数据泄漏、hard-negative 负迁移、CoT 过矫正、对比 CoT 判别焦虑等数据/方法论瓶颈,并验证 DPO 在 16 GB 显存上不可行(8bit OOM、4bit 梯度失效);随后将数据构建升级为 **DeepSeek V4-Flash / Kimi K3 / GLM-5.2 三模型 API 蒸馏**,产出 7692 条大规模训练数据,在云端 **A800 GPU** 上完成 v9max 训练。v9max 在 87 段合成集上漏报清零(recall 1.000)、CWE 严格召回率 45.9%→60.7%,在 20 段真实 CVE-fix 上 recall 达 0.95,大幅增强漏检检出能力并已量化发布为 Ollama 模型。

最终模型定位为 **Nivis-alpha.1**(在 v9max 基础上完成 DPO/GRPO 偏好优化、数据飞轮与 CoT 教学后收敛),v9max 是其中已发布的关键里程碑。整个链路证明:消费级 GPU 上 QLoRA SFT 可显著提升 8B 模型的漏洞检出与 CWE 归因,但大规模数据与偏好优化需云端 A800 级算力放大。

## 论文写作规范约定

### 引用与文献

- 中文毕业论文采用 GB/T 7714-2015 著录格式
- 文中引用用 `[数字]` 上标,如 rsLoRA `[1]`、KnItLM `[2]`
- 文献按出现顺序编号,集中在文末参考文献章节
- 主要待引文献清单(待补):
  - rsLoRA: Hayou et al. 2024
  - DoRA: Liu et al., ICLR 2024
  - KnItLM: ICLR 2026 投稿(需核实发表状态)
  - Prompt Distillation: TMLR 2025
  - DPO: Rafailov et al. 2023
  - GaLore: Zhao et al., arXiv:2403.07404
  - Qwen2.5-Coder 技术报告
  - Bandit / Semgrep / CodeQL 官方文档
  - OWASP Top 10 / CWE Top 25

### 术语与命名

- 模型名首次出现给全称,如 Qwen2.5-Coder-7B-Instruct,后续简写为 qwen2.5-coder:7b
- 缩写首次出现给全称,如 Continual Pre-Training (CPT)
- 中文术语优先,英文括注,如 "继续预训练(Continual Pre-Training, CPT)"
- 实验编号统一用 exp_01~exp_06,与代码仓库一致

### 表格与图示

- 每张表/图必须有编号与标题,如 "表 4-1 exp_01 14 段样本检测结果"
- 数据表来源在表脚用小字标注,如 "数据来源: results.qwen2.5-coder-7b.json"
- 训练曲线、混淆矩阵等图示待用 matplotlib 生成,保存为 PNG 后插入

### 章节编号

- 一级章节: 第N章
- 二级章节: N.M
- 三级章节: N.M.K
- 图表编号: 图 N-M / 表 N-M(章内连续编号)
