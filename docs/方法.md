# 研究方法体系

> 本文档梳理本项目（exp_06_finetune）实际采用的研究方法与技术路线。当前主线为 **Qwen3-8B-Instruct + QLoRA SFT + DPO 尝试**，2026-07-22 前基于 Qwen2.5-Coder-7B 的 KnItLM/Prompt Distillation 路线已归档，见 `docs/_archive/方法_20260719_qwen25.md`。

---

## 一、总体技术路线

本研究采用"零样本基线 → 无训练增强 → 监督微调 → 偏好优化"的递进路线：

```text
exp_01~05：零样本推理基线
  └─ Qwen2.5-Coder-7B 零样本判断、RAG 增强、Prompt 工程、传统工具对比

exp_06 P0：评估基础设施修复
  └─ 切换 Qwen3-8B，max_tokens 1024→2048，parse_fail 归零，建立新锚点

exp_06 P1：CVE-fix 真实集校准
  └─ NVD-by-CWE 抓取 8 个真实 CVE-fix，确认合成集虚高 59.2pp

exp_06 P2：QLoRA SFT 数据迭代
  └─ v2/v3/v4/v5/v6 五个数据版本，最终 v5 为当前最佳

exp_06 P3：DPO 尝试
  └─ 本地 16GB GPU 不可行（8bit OOM、4bit 梯度失效），数据保留待云 GPU 复用
```

## 二、模型基座与量化

### 2.1 基座选择

| 阶段 | 基座模型 | 说明 |
| --- | --- | --- |
| exp_01~05 | Qwen2.5-Coder-7B-Instruct | 零样本推理与 Prompt 工程 |
| exp_06 P0~P3 | Qwen3-8B-Instruct | 2026-07-22 切换，统一训练与评估基座 |

选择 Qwen3-8B 的原因：
- 与 Qwen2.5-Coder-7B 相比，Qwen3-8B 在代码理解与指令遵循上更强；
- chat template 更规范，便于统一训练数据格式；
- 需显式禁用 thinking 模式，避免 CoT 输出被 `<think>` 标签包裹。

### 2.2 量化策略

训练与推理均使用 bitsandbytes 4-bit NF4 量化：

```python
# 核心配置
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",
)
```

- **NF4**：对正态分布权重最优的 4-bit 量化类型；
- **double quant**：对量化常数再次量化，进一步省显存；
- **bfloat16 计算**：在 ROCm 7.2 + RDNA4 上稳定，避免 fp16 溢出。

8B 模型 4bit 量化后权重约 4.5 GB，加上 LoRA 梯度、优化器状态、激活值，SFT 单 epoch 峰值显存约 12-14 GB，可在 16 GB 消费级 GPU 上完成。

## 三、参数高效微调：QLoRA + rsLoRA

### 3.1 LoRA 配置

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| `r` | 8 | 8B 强基座上 r=8 已能做轻量技能注入；增大到 32 在 Qwen2.5 时代已证明会引入过拟合 |
| `lora_alpha` | 16 | 保持 alpha = 2r 的常规比例 |
| `lora_dropout` | 0.1 | 训练样本 749 条，小数据需 dropout 防过拟合 |
| `target_modules` | q/k/v/o_proj + gate/up/down_proj | 覆盖注意力与 FFN，不引入 embed/lm_head 避免破坏词表 |
| `use_rslora` | True | 缩放因子从 `1/r` 改为 `1/√r`，高 rank 更稳定；对 r=8 零额外成本 |
| `use_dora` | False | DoRA 在 ROCm 4bit 上兼容性需验证，且 2026 实证研究显示 LoRA 变体在 lr 调优后差距仅 1-2% |

### 3.2 训练超参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `epochs` | 3 | 配合 EarlyStopping，实际通常 2-3 epoch 收敛 |
| `learning_rate` | 1e-4 | Phase 1 sweep 在 Qwen2.5 时代验证 lr=1e-4+rsLoRA dev_loss 最低；迁移到 Qwen3-8B 后直接复用 |
| `per_device_train_batch_size` | 1 | 16GB 显存约束 |
| `gradient_accumulation_steps` | 8 | 全局 batch size = 8 |
| `max_seq_length` | 2048 | 避免长 CoT 被截断（P0 关键修复） |
| `lr_scheduler_type` | cosine | 标准选择 |
| `warmup_ratio` | 0.03 | 小数据集稳定训练 |
| `early_stopping_patience` | 2 | 按 eval_loss 选 best，防止过拟合 |

### 3.3 ROCm/RDNA4 训练加速

| 优化项 | 环境变量/配置 | 效果 |
| --- | --- | --- |
| AOTRITON attention | `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1` | step time -50% 以上（实测 Phase 2 31s/step vs Phase 1 73-76s/step） |
| TunableOp | `PYTORCH_TUNABLEOP_ENABLED=1` + 离线调优 | 额外 <5% 加速，调优成本高，本项目仅部分调优 |
| bitsandbytes | `paged_adamw_8bit` | 省显存；gfx1200（RX 9060 XT）未出现报告的静默损坏 |

## 四、数据工程

### 4.1 数据格式

所有训练样本统一为 ChatML 格式：

```json
{
  "messages": [
    {"role": "system", "content": "<system prompt>"},
    {"role": "user", "content": "<代码片段>"},
    {"role": "assistant", "content": "<CoT 推理 + 结构化 verdict>"}
  ]
}
```

关键设计：
- **推理→标签**：assistant CoT 从污染源追踪开始，逐步推导至结论，而非从标签反推理由；
- **Qwen3 thinking 禁用**：`apply_chat_template` 设置 `enable_thinking=False`，避免输出被 `<think>` 标签包裹；
- **结构化输出**：verdict 固定为 JSON 字段 `vulnerable` / `cwe` / `explanation` / `fix`，便于解析。

### 4.2 数据版本迭代

| 版本 | 样本数 | 核心变更 | 状态 |
| --- | --- | --- | --- |
| v2 | 823 | 复用 Qwen2.5 时代数据 | 已完成 |
| v3 | 832 | CWE 统一 + 107 条 CoT 重写 + 9 条 LDAP 补充 | 已完成 |
| v4 | 839 | 反清单式 prompt + 19 条 hedge 修复 + 7 条 CWE-441 | 因训练-测试泄漏被废弃 |
| **v5** | **749** | **清洗 100 条泄漏/近泄漏样本 + 10 条弱密码学** | **当前最佳** |
| v6 | 755 | v5 + 6 个 FP 正确拒绝 CoT | 负迁移，已归档 |

### 4.3 训练-测试泄漏审计

v4 被发现存在系统性泄漏后，建立审计流程：

1. **精确匹配**：检查训练样本与测试样本是否完全一致；
2. **行级 Jaccard 重叠**：对每对训练-测试文件计算 3 行滑动窗口的 Jaccard 相似度；
3. **阈值**：>30% 视为高重叠，>15% 视为中重叠；
4. **处理**：高重叠直接删除，中重叠人工复核。

该流程由 `experiments/exp_06_finetune/scripts/audit_leakage_precise.py` 实现。

## 五、评估方法

### 5.1 测试集

| 测试集 | 样本数 | 用途 |
| --- | --- | --- |
| 87 段合成集 | 87 | 覆盖 34 类 CWE，4 种语言，用于迭代评估 |
| 8 段 CVE-fix | 8 | 真实 GitHub commit 修复前代码，用于泛化验证 |

### 5.2 评估指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| `recall` | TP / (TP + FN) | 检出能力 |
| `FPR` | FP / (FP + TN) | 误报率 |
| `accuracy` | (TP + TN) / 总数 | 综合正确率 |
| `strict_recall` | CWE 编号完全正确的 TP / (TP + FN) | CWE 归因精确度 |
| `parse_fail` | 模型输出无法解析为 verdict 的样本数 | 评估基础设施健康度 |

### 5.3 评估方式

- **本地推理**：通过 Ollama API 调用 4bit 量化模型，设置 `keep_alive=300`（5 分钟）避免永久占用显存；
- **批量评估**：`evaluate.py` 逐样本调用，结果以时间戳命名保存为 JSON；
- **每次必登**：新评估结果必须追加到 `EXPERIMENT_LEDGER.md`。

## 六、DPO 尝试与失败分析

### 6.1 DPO 配置

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `beta` | 0.1 | DPO 温度参数 |
| `learning_rate` | 5e-7 | 保守学习率 |
| `epochs` | 1 | 偏好对 104 条，1 epoch 即可 |
| `max_length` | 512 | 缩短序列以省显存 |
| `max_prompt_length` | 256 | 缩短 prompt 以省显存 |

### 6.2 失败记录

| # | 配置 | 结果 | 根因 |
| --- | --- | --- | --- |
| 1 | 8bit + max_len=1024 | OOM 黑屏 | 8B 8bit + policy/reference 双前向超 15GB VRAM |
| 2 | fp16 + max_len=512 | 立即 OOM | 8B fp16 本身就超 16GB |
| 3 | 4bit + max_len=512 | 跑完但 grad_norm=0 | 4bit NF4 + 双前向梯度无法回传到 LoRA 层；dmesg 记录 amdgpu drm panic |

### 6.3 结论

本地 16GB 消费级 GPU 无法训练 8B DPO。偏好对数据 `dpo_merged.jsonl` / `dpo_fp_pairs_v5.jsonl` 已保留，待换用 24GB+ GPU 或云实例后复用。

## 七、关键方法论结论

1. **数据可信度 > 模型容量**：v4 因训练-测试泄漏产生漂亮但不可信的指标；v5 清洗后指标更可信，也更能指导后续决策。
2. **简单 hard-negative 得不偿失**：v6 为降 FPR 追加 FP 正确拒绝 CoT，反而牺牲 recall 与 CVE-fix 泛化。
3. **消费级 GPU 存在方法边界**：QLoRA SFT 可行，DPO 不可行。
4. **真实 CVE 评估不可替代**：合成集 recall 1.000 不能代表真实漏洞泛化能力，CVE-fix 评估暴露持续 FN。

## 八、复现命令速查

```bash
# SFT v5（当前最佳）
HF_HUB_OFFLINE=1 TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1 \
  python3 \
  experiments/exp_06_finetune/scripts/train_qlora.py \
  --data-file ../data/train_chatml_v5_clean.jsonl \
  --output-dir ../outputs/lora_r8_a16_e3_lr0.0001_s42_rslora_v5 \
  --epochs 3 --lr 1e-4 --seed 42 --use-rslora

# 评估 v5
python3 experiments/exp_06_finetune/scripts/evaluate.py \
  --model-path outputs/lora_r8_a16_e3_lr0.0001_s42_rslora_v5/best \
  --test-file experiments/exp_06_finetune/testset_v3_34cwe/fix_after_v3.jsonl \
  --max-new-tokens 2048

# DPO（本地不可行，仅供云 GPU 复用）
HF_HUB_OFFLINE=1 TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL=1 \
  python3 \
  experiments/exp_06_finetune/scripts/train_dpo.py \
  --sft-adapter outputs/lora_r8_a16_e3_lr0.0001_s42_rslora_v5/best \
  --data-file ../data/dpo_merged.jsonl \
  --epochs 1 --beta 0.1 --lr 5e-7 --seed 42
```

> 注意：复现命令使用通用 `python3`，实际运行时请确保已激活对应的 conda 环境（`graproj` 或 `AI`）。
