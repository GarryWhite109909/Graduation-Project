# 实验脚本审查遗留问题

> 本文档记录 2026-07-22 对 exp_01-06 全部实验脚本审查后，**需要重跑实验或重生成数据才能解决**的方法论问题。代码层面的问题已在本次审查中全部修复，此处仅列出无法通过纯代码修复的遗留项。

## 一、需重跑训练/评估的问题

### 1.1 多种子评估 metrics 历史结果仅含 run1【严重】

**位置**：`experiments/exp_06_finetune/scripts/evaluate.py`

**现状**：代码已修复，新增 `metrics_mean` 字段保存多种子均值。但**已生成的历史评估 JSON 文件**（如 `exp_06_eval.phase1_lr1e-4.20260718_160554.json` 等）中只有 `metrics`（来自 run1），没有 `metrics_mean`。

**影响**：下游 `compare_results.py`、`compare_4way.py` 等对比脚本已改为优先读取 `metrics_mean`，但对历史文件仍会回退到 `metrics`（run1 偶然结果）。

**解决**：重跑多种子评估生成含 `metrics_mean` 的新 JSON，或在论文中说明历史对比基于 run1。

### 1.2 CPT LoRA 在 Base 上训练，合并到 Instruct 权重【严重】

**位置**：`experiments/exp_06_finetune/scripts/merge_lora_to_instruct.py` + `compare_phase3.py`

**现状**：Phase 3 的 CPT LoRA 在 Qwen3-8B-Base 上训练，却合并到 Qwen3-8B (Instruct) 权重。LoRA delta 是相对 Base 学习的偏移，加到 Instruct 上数学上不严格成立。

**影响**：Phase 3 vs Phase 1 的对比（strict recall +23pp）混淆了"CPT 知识注入效果"与"权重基底错位噪声"。

**解决**：补一个对照组实验——Qwen3-8B-Base（无 CPT）合并到 Instruct 后评估，以隔离合并操作本身的影响。若对照组指标与 Phase 1 baseline 接近，说明合并操作影响小；若差异大，需在论文中说明。

### 1.3 DPO 偏好对 rejected 全同【严重】

**位置**：`generate_dpo_pairs.py` + `generate_ccot_v3_expansion.py`

**现状**：代码已添加 TODO 注释和 `<|im_end|>` 补全。但**已生成的 `dpo_preference_pairs.jsonl` 和 `dpo_v3_expansion.jsonl`** 中所有安全样本的 rejected 仍是同一句"CWE-78 命令注入/High/改用参数化查询"。

**影响**：DPO 模型学到的是"压制固定文本"而非"为什么错"。fix 与漏洞类型不匹配（参数化查询是 SQL 防御，与 CWE-78 命令注入无关）。

**解决**：修改 `build_wrong_verdict` 函数按样本 CWE 类型生成语义相关的错误结论，重新生成 jsonl，重跑 DPO 训练。

### 1.4 课程学习闭环未实现【严重】

**位置**：`curriculum_scheduler.py` + `train_qlora.py`

**现状**：`curriculum_scheduler.py` 生成的配置文件含三阶段样本索引和 replay_ratio=0.3，但 `train_qlora.py` 没有 `--curriculum-phase` 和 `--curriculum-config` 参数。`replay_ratio` 仅写入 JSON，采样逻辑未实现阶段间回放。

**影响**：课程学习（A→B→C 阶段 + 0.3 replay）完全未生效。

**解决**：在 `train_qlora.py` 中添加 `--curriculum-phase` 和 `--curriculum-config` 参数，实现阶段切换和 replay 采样逻辑，重跑训练。

### 1.5 P1-5 消融 D 组"等长"控制变量不成立【严重】

**位置**：`experiments/exp_04_hard_samples/run_rag_experiment.py`

**现状**：代码已修复，`build_irrelevant_context` 支持按目标长度动态匹配。但**已生成的 `results.ablation.irrelevant.topk3.qwen7b.v3.json`** 中 D 组用的是固定 1500 字符。

**影响**：A vs D 的差异混入了长度因素，消融核心结论"提升来自知识相关性而非 prompt 变长"存疑。

**解决**：重跑 P1-5 消融 D 组，传入 A 组 RAG 实际长度。

### 1.6 exp_04 多模型对比仍用旧模型【中等】

**位置**：`experiments/exp_04_hard_samples/run_v3_multi_model.sh`

**现状**：多模型对比仍用 qwen2.5-coder/gemma4/deepseek/gpt-oss 等旧模型，无 Qwen3-8B。

**影响**：第六章多模型结论（基于旧模型）与当前基座脱节。

**解决**：重跑多模型对比，加入 Qwen3-8B；或在论文中明确标注该结论适用范围。

### 1.7 probe_model 判定逻辑变更影响 mastered/fuzzy 分布【中等】

**位置**：`probe_model.py`

**现状**：代码已修复——`judge_attribution` 在 expected_cwe 为空时返回 None（非 True），`judge_concept` 回退逻辑收紧。但**已生成的 `probe_report_qwen3.json`** 是用旧逻辑跑的。

**影响**：既有探测报告中 mastered/fuzzy/error 分布可能不准确（部分 CWE 被误判为 mastered）。

**解决**：重新运行 `probe_model.py` 生成新报告，并据此重新生成 CPT 语料（`prepare_cpt_corpus.py --probe-report`）。

### 1.8 supplement_hard_samples 标签修改需重新生成 jsonl【中等】

**位置**：`supplement_hard_samples.py`

**现状**：代码已修复——文件上传样本改为 `has_vulnerability=True`（CWE-22），整数溢出样本改为 `has_vulnerability=False`。但**已生成的 `supplement_chatml.jsonl`** 含旧标签。

**影响**：若 `supplement_chatml.jsonl` 已参与训练，模型学到了错误标签。

**解决**：重新运行 `supplement_hard_samples.py` 生成新 jsonl，重跑 SFT 训练。

### 1.9 SYSTEM_PROMPT schema 不统一【中等】

**位置**：多个 supplement 脚本

**现状**：代码已修复——所有 supplement 脚本统一使用 `SYSTEM_PROMPT_LITE`。但**已生成的 jsonl 文件**中 system prompt 可能仍是旧版本（有的含 `taint_path`，有的不含）。

**影响**：训练集中 system prompt schema 不统一，模型学到两种 JSON 输出约定。

**解决**：重新运行所有 supplement 脚本生成新 jsonl，重跑训练。

## 二、需重新生成数据的问题

### 2.1 CPT 语料缺失 v1 蒸馏数据【严重】

**位置**：`prepare_cpt_corpus.py`

**现状**：代码已修复——添加了跳过计数和警告。但**已生成的 `cpt_corpus.jsonl`** 中 v1 蒸馏数据（`distill_corpus_annotated.jsonl`）因格式不匹配被静默跳过。

**影响**：CPT 语料缺失 v1 蒸馏数据，模型未学到这部分推理链路。

**解决**：修复 `extract_reasoning_from_chatml` 对原始标注格式的支持，或先将 v1 蒸馏数据转为 ChatML 格式，重新生成 `cpt_corpus.jsonl`，重跑 CPT 训练。

### 2.2 Layer B 未做 probe 靶向过滤【严重】

**位置**：`prepare_cpt_corpus.py`

**现状**：代码已修复——Layer B 主循环添加了 probe 过滤。但**已生成的 `cpt_corpus.jsonl`** 中 Layer B 包含所有 CWE 的 ChatML 推理样本（未过滤已掌握 CWE）。

**影响**：注入已掌握 CWE 知识会导致表示空间排斥，可能是 CPT "爆炸"的根因。

**解决**：重新运行 `prepare_cpt_corpus.py`（需先重新生成 probe_report，见 1.7），重跑 CPT 训练。

### 2.3 DPO chosen/rejected 缺 `<|im_end|>`【严重】

**位置**：`generate_dpo_pairs.py` + `generate_ccot_v3_expansion.py`

**现状**：代码已修复——添加了 `<|im_end|>` 补全。但**已生成的 jsonl 文件**中 chosen/rejected 不含 `<|im_end|>`。

**影响**：DPO 模型可能学不会停止生成。

**解决**：重新生成 DPO 数据，重跑 DPO 训练。需确认 `train_dpo.py` 是否自动补 token——如果自动补，则影响较小。

### 2.4 CVE-fix 测试集标签噪声【严重】

**位置**：`adapter_cve_fix_manifest.py`

**现状**：代码已修复——auth/authen 顺序纠正，宽泛关键词收紧。但**已生成的 `manifest_eval.json`** 含旧标签（auth 类误标 CWE-862，path/key/hash 误标 CWE-22/798/327）。

**影响**：CVE-fix 测试集 expected_cwe 充满噪声，评估指标失真。

**解决**：重新运行 `adapter_cve_fix_manifest.py` 生成新 manifest，重跑 CVE-fix 评估。

### 2.5 merge_supplements 的 source 字段覆盖【严重】

**位置**：`merge_supplements.py`

**现状**：代码已修复——改用 `_source` 内部字段。但**已生成的合并 jsonl** 中 source 字段可能已被覆盖。

**影响**：若记录原本携带 source/sink 元数据，会被静默覆盖。

**解决**：重新运行 `merge_supplements.py` 生成新合并数据。

### 2.6 augment_data.py 增强数据不可复现【严重】

**位置**：`augment_data.py`

**现状**：代码已修复——`hash()` 改为 `hashlib.md5`，PROTECTED_NAMES 生效。但**已生成的增强数据**是用旧逻辑跑的，不可复现且可能含语法错误（`input`/`filter` 被替换）。

**影响**：若增强数据已参与训练，模型学到了非法 Python 代码。

**解决**：确认 `augment_data.py` 是否仍在使用（`combine_and_augment.py` 已声明弃用此脚本策略）。若已弃用，删除脚本；若在用，重新生成增强数据。

## 三、需补充实验的问题

### 3.1 P1-5 消融无重复实验【中等】

**位置**：`experiments/exp_04_hard_samples/run_v3_qwen7b_all.sh`

**现状**：P1-5 消融 4 组用 `--repeat 1`，无重复实验，无法对 A/B/C/D 差异做统计显著性检验。

**影响**：报告/论文若称"RAG 显著优于"，缺乏统计支撑（仅点估计对比）。P1-4 用 repeat=3 有 CI，P1-5 无。

**解决**：重跑 P1-5 消融用 `--repeat 3`，然后用 `bootstrap_significance.py` 做显著性检验。

### 3.2 DPO 无验证集评估和 best 模型选择【中等】

**位置**：`train_dpo.py`

**现状**：代码已修复——DPOConfig 添加了 `eval_strategy`/`metric_for_best_model`/`load_best_model_at_end`，DPOTrainer 传入了 `eval_dataset`。但**已训练的 DPO 模型**是旧逻辑跑的（保存的是最终状态而非 dev_loss 最优）。

**影响**：无法检测 DPO 过拟合，保存的 `best/` 实际是最终状态而非最优。

**解决**：重跑 DPO 训练，使用新的 best checkpoint 选择逻辑。

### 3.3 prompt 投放方式跨实验不统一【中等】

**位置**：`experiments/exp_01_basic_scan/run_experiment.py` vs `exp_03_rag_knowledge/run_rag_experiment.py`

**现状**：exp_01 用 `build_full_prompt`（单 prompt，无 system 角色），exp_03/04-rag/05 用 `build_user_prompt + system_prompt` 分离传入。对 Qwen3（chat API 走 system role）两者模板不同。

**影响**：exp_01 vs exp_03 对比存在 prompt 投放方式的系统性混淆变量。

**解决**：统一为分离的 system/user 方式，重跑 exp_01。或在论文中说明 prompt 投放方式的差异。

### 3.4 跨文件样本处理不统一【中等】

**位置**：`exp_04_hard_samples/run_experiment.py` vs `run_rag_experiment.py`

**现状**：P1-4（`run_experiment`）与 exp_05 注入 `_input` 上下文，P1-5（`run_rag_experiment`）与多模型对比不注入。

**影响**：跨文件样本（`hard_crossfile_*_sink`）在三组实验中条件不同，影响横向对比。

**解决**：统一跨文件样本处理（全部注入或全部不注入），重跑相关实验。

**说明**：见 1.1。论文中多种子对比实际是"第一次抽样偶然结果对比"，需说明或重跑。

**位置**：`bootstrap_significance.py`

**现状**：代码未修改（属于方法论选择）。用 bootstrap 分布中 ≤0 和 ≥0 的比例近似 p 值，非标准做法。标准应中心化后计算超过观测差值的比例。

**说明**：论文中报告 p 值时需说明计算方法，或改用标准方法重新计算。

### 4.4 generate_report.py "核心结论"硬编码

**位置**：`experiments/exp_04_hard_samples/generate_report.py`

**现状**：代码已添加 TODO 注释。第六章"核心结论"为硬编码文本，不从数据计算。

**说明**：若底层结果文件变化（重跑/换模型），表格（动态计算）与结论（静态）可能不一致。论文引用这些数字时需手动核对。

### 4.5 exp_01 基线指标硬编码

**位置**：`generate_report.py`

**现状**：代码已添加 TODO 注释。exp_01 基线指标（100%/0%/100%）硬编码，未从结果文件读取。
